# 家計簿

Vue 3・Cloudflare Pages・D1 を利用した日本語の家計簿 PWA です。明細・統計・電子マネー残高・SBI 投資信託の保有情報を管理します。

## 主な機能

- 手入力、テキスト解析、レシート・カード明細の画像読取、店舗・支払方法のルール設定
- 月次・年次統計、カテゴリ別集計、カレンダー、重複候補の確認
- クレジットカード・プリペイドカード、チャージ・利用・振替の残高管理
- 固定費の登録、SBI 投資信託の保有情報・積立予定、基金の基準価額
- 端末内 OCR と、明示的に有効化した場合の Cloudflare AI 画像認識（利用回数の上限あり）
- D1で同期する確認履歴・下書き、端末ごとに保持するテーマカラー、非公開R2のレシート画像保存（既存の端末画像は検証後に移行）、JSON バックアップ・復元

アプリ名と画面文言は日本語です。過去の中国語カテゴリ ID は既存記帳データを保護するため維持し、画面表示だけ日本語に変換します。

## 開発とテスト

Node.js 22 を利用します。

```bash
npm ci
npm run verify:release
```

`verify:release` は回帰テスト（`node --test scripts/*.test.js`）、本番依存のセキュリティ監査、Vite ビルドを実行します。

ローカル確認：`npm run cf:dev`。PR マージ前には [リリース前チェック](.github/PULL_REQUEST_TEMPLATE.md) に従い、GitHub Actions の Validate と必要な Mobile WebKit Smoke、およびローカルの回帰テストを確認します。Cloudflare Pages と NAV Worker の自動 Preview は無効化済みで、テスト用 D1 も廃止しました。静的ビルド成功だけで、実機 Safari や本番 Cron の稼働まで保証されるわけではありません。

## D1 無料枠を守る開発方針

新機能は [D1無料枠優先の設計方針](docs/d1-free-tier-policy.md) に従い、`rows_read`・`rows_written` を可能な範囲で減らします。単にSQLをまとめるだけでなく、日付範囲の索引利用、画面内の取得済みデータ再利用、冪等な書き込み、不要なCronアクセス削減を優先します。

## Cloudflare の構成

- `wrangler.toml`：Pages 用設定。本番 D1 の `DB`、非公開 R2 `RECEIPTS_R2`、必要に応じた `AI` バインディング。Preview の D1/R2 は無効
- `wrangler.nav.toml`：**既存の1つの Worker** `kakeibo-nav-sync`。固定費を日本時間 00:30 と 09:30 に D1 へ自動記帳し、基準価額を 19:30 と 23:15 に同期。NAV と固定費の処理は Cron ごとに独立。新規 Worker は不要
- NAV 同期の操作・取得可能な基金については [scripts/deploy-nav-worker.md](scripts/deploy-nav-worker.md) を参照

新規環境では D1 のスキーマ移行手順を [migrations/README.md](migrations/README.md) で確認してください。**運用中の D1 に `schema.sql` を再実行して初期化しないでください。** マイグレーションは明示的なレビュー後に適用し、通常の API 呼び出しで旧テーブルやテストデータを再作成しません。

## プレビュー環境とデータ保護

2026-11-12 に `kakebo_preview` D1 を廃止し、Cloudflare Pages の自動 Preview デプロイと `kakeibo-nav-sync` の Worker Previews を停止しました。Pages Preview および NAV Worker Preview に D1 をバインドしません。既存プレビューのデータベース API は利用対象外です。

**本番 D1（`kakebo`）をプレビューで共有しないでください。** 将来プレビューを再有効化する場合は、本番と完全に分離された新しいテスト用 D1・認証情報を作成し、環境分離の安全性を検証してから有効化してください。通常の PR 検証は GitHub Actions とローカルテストで行います。

ログインには `AUTH_TOKEN` を使用します。端末セッションは取り消し可能で有効期限は最大 30 日です。アクセストークンを公開リポジトリやログに貼り付けないでください。

## バックアップ・復元

現在の新規 JSON バックアップは **v4** で、SHA-256 整合性情報を含みます。既存の v1〜v3 も読み取り対象ですが、旧版には現在の保有情報などが含まれない場合があります。**レシート画像は非公開R2へ保存し、自動削除せず、JSON には含めません。**「帳簿＋画像をまとめてZIP保存」で画像を含めて保管し、復元時には ZIP をそのまま選択できます。画像は明細 ID が一致する場合か、取引内容と復元 ID を検証できた場合にのみ非公開R2へ復元され、既存画像は上書きされません。画像が一致しない場合・端末の保存容量が不足する場合は未復元件数が表示されます。

復元では既存の明細・カード・SBI 保有データを削除したり上書きしたりせず、追加対象を確認してから重複防止 ID を付与します。大量のデータは **1 回の一括トランザクションではなく、それぞれ原子的な分割バッチ** で処理し、中断時に完了済み件数を示して再試行できます。プリペイド残高を復元する場合、将来日のチャージ・振替は期首残高へ先取りせず、再基準化後に登録して予定日に反映させます。

重要な変更後は別のバックアップを取り、独立したテスト用 D1 で復元を検証してください。実際の資産残高、SBI の約定・入金、旧端末でまだR2移行が完了していない画像はこのバックアップだけでは検証・再現できません。

## 注意

SBI の資産移動反映は家計簿上の記録です。証券口座への着金や買付完了を保証しません。MUFG の対応銘柄は公式 API で NAV を取得し、大和 NASDAQ100（04317188）はアクセス制限により自動取得を停止し手入力を維持します。

既存の明細・分類ルール・SBI 保有口数・取得金額・評価額を削除、初期化、自動再計算しないでください。
